- `.gitignore` — add Python entries: `__pycache__/`, `*.pyc`, `.venv/`, `.mypy_cache/`,
  `.ruff_cache/`, `.pytest_cache/`.

**Domain layer (new)** — plain Python, no FastAPI/Pydantic import (architecture.md forbidden-deps
rule)
- `roombook/__init__.py`
- `roombook/domain/__init__.py`
- `roombook/domain/models.py` — `Room`, `TimeSlot`, `Booking` as frozen dataclasses (structural
  shape only — no business-rule validation here; BR-1/2/3 live in `service/`).
- `roombook/domain/clock.py` — `Clock` protocol (`now() -> datetime`) + `SystemClock` default
  implementation, so "current time" is injectable and tests can control it (see Risk R-1).

**Service layer (new)** — framework-agnostic, unit-testable without HTTP
- `roombook/service/__init__.py`
- `roombook/service/errors.py` — `RoomNotFoundError`, `InvalidTimeSlotError`,
  `BookingConflictError` (carries the overlapping `Booking`s and computed suggestion `TimeSlot`s).
- `roombook/service/booking_service.py` — `create_booking(...)`: validates the room exists, builds
  and validates the `TimeSlot` (BR-2, BR-3, tz-aware requirement), checks BR-1 against the room's
  existing bookings, and on conflict computes up to 3 suggested free `TimeSlot`s (same duration,
  same room, >= requested start, within the 7-day horizon).

**Repository layer (new)** — the only module holding storage state
- `roombook/repository/__init__.py`
- `roombook/repository/interfaces.py` — `RoomRepository`, `BookingRepository` Protocols.
- `roombook/repository/in_memory.py` — `InMemoryRoomRepository`, `InMemoryBookingRepository`.
- `roombook/repository/seed.py` — a small fixed set of example rooms used to seed the *running
  app* (not tests — tests use their own isolated fixtures).

**API layer (new)** — wire format only
- `roombook/api/__init__.py`
- `roombook/api/schemas.py` — `CreateBookingRequest` (room_id, start, end, organizer, title, with a
  Pydantic validator rejecting naive datetimes — AC-15), `BookingResponse`, `ConflictDetail`,
  `SuggestedSlot`, `ConflictResponse`, `ErrorResponse`.
- `roombook/api/dependencies.py` — FastAPI dependency providers for the repositories/service/clock,
  overridable in tests.
- `roombook/api/routers/__init__.py`
- `roombook/api/routers/bookings.py` — `POST /bookings`; maps `RoomNotFoundError` → 404,
  `InvalidTimeSlotError` → 422, `BookingConflictError` → 409 with conflict + suggestion detail,
  success → 201.
- `roombook/api/main.py` — FastAPI app factory, mounts the router, wires default (seeded) deps.

**Tests (new)**
- `tests/unit/test_booking_service.py`
- `tests/api/test_bookings_router.py`
- `tests/conftest.py` — shared fixtures: fixed `Clock`, isolated in-memory repos pre-loaded with a
  known test room, `TestClient` with dependency overrides.

## Risks & open questions

- **R-1: Clock injection.** AC-13 requires testing both "start in the past" and "start exactly
  equal to now" deterministically — not reliably testable against real wall-clock time. *Recommendation:* introduce the `Clock` protocol (step 2) and inject it through the service and API
  dependency layers; tests supply a fixed `Clock`. This is a plan-level design decision, not a
  spec change.
- **R-2: Where validation errors originate.** `TimeSlot`/`Booking` in `domain/models.py` are kept
  as plain shape-only dataclasses; all BR-1/2/3 and tz-awareness validation happens in
  `service/booking_service.py`, which raises the typed domain errors directly. *Recommendation:*
  do this rather than raising from `__post_init__`, so every validation failure funnels through
  one place with one error-type story, matching `docs/conventions.md`'s error-handling rule.
- **R-3: Conflict/suggestion response shape.** The spec deliberately leaves wire format
  unspecified. *Recommendation:* `409` body = `{"error": "conflict", "conflicts": [{"start",
  "end", "title"}], "suggestions": [{"start", "end"}]}`; `404`/`422` bodies = `{"error": "<code>",
  "message": "<safe message>"}` — no stack traces or internals (`docs/security.md`).
- **R-4: Seed data for the running app.** Not covered by any AC (Room management is out of scope),
  but the app needs to be runnable/manually exercisable. *Recommendation:* `repository/seed.py`
  ships 2 example rooms; tests never depend on this seed — they inject their own fixture room via
  dependency override, so seed changes can never silently affect test behavior.
- **R-5: `httpx` dependency.** FastAPI's `TestClient` requires `httpx` as of recent FastAPI
  versions. *Recommendation:* add as a dev dependency; flagging so it doesn't look like scope
  creep in the diff.
